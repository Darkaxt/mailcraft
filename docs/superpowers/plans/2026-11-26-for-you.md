# For you, pane auto-hide and folder & subject rows: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A live "For you" section at the top of All mail and Inbox, a reading pane that hides when nothing is selected, and a folder-led row layout.

**Architecture:** A new engine module `for_you` computes, per list build, which unread messages qualify and in which tier, from per-sender statistics over the local mailbox; `list::listing` moves those rows to the top under a "For you" heading. Settings live in `Prefs`; the only new per-message state is a local `link_opened` time. The egui UI adds the section header, a settings window, the row layout and the pane rule.

**Tech Stack:** Rust (workspace forbids `unsafe`), egui/eframe, existing engine `Session`/`Prefs`/`list` and `ui-egui` crates.

**Spec:** `docs/superpowers/specs/2026-11-26-for-you-design.md` (read it with this plan).

## Global Constraints

- Owner rule: **no compilation until the whole change is written**. Write every task's tests and code first; the only builds and test runs are Task 8's, through the Coordinator rust-gate (build-prepare readiness file from `D:/Tools/MailCraft/maintenance/release-templates/make_ready.py`). At most 3 corrections per check.
- Windows x64 only; no new dependencies.
- Fork feature: new code in new files (`for_you.rs`, `for_you_tests.rs`, `ui-egui/src/for_you_view.rs`); edits to upstream files kept to small hooks, each marked `// fork: For you`.
- Never changes mail state: no command of this feature marks read, moves, pins or deletes.
- Agent consent: For you list/read commands are Safe; changing For you settings is a settings change (same class as `file.options`); clearing the link history is Safe (local, owner data about his own clicks, no mail affected).
- Every new user-visible string through `tl!`/`tl_later!`; catalogues regenerated by the `windows-i18n-write` check.
- Spec values: new sender window 1 month (30 days); reply tier: 1 answered among the last 10 received; links and read tiers: more than half of the sender's mail in the last 2 months (61 days); cap 15; per-folder age limit default none.

## Review Focus

1. A sender with exactly 2 messages in the window, 1 read: "more than half" means 1 of 2 does **not** qualify (strictly greater than 50%).
2. An unread message that is also manually pinned: it stays in "Pinned" (manual pins win) and is not duplicated in For you.
3. A conversation where the newest message is read but an older one is unread and qualifies: the conversation row goes to For you, counted once.
4. A message carrying sender warnings from a sender he always reads: never in For you.
5. Inbox view with 20 messages from switched-on folders and a cap of 15: all 20 show (switched-on folders are never capped); tier mail after them is capped.

**Interfaces:**
- Produces:
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)] pub enum Tier { Folder, NewSender, Replied, Links, Read }` (declaration order = display order).
  - `pub struct ForYouPrefs { pub all_mail: bool, pub inbox: bool, pub new_sender: bool, pub new_sender_days: u16, pub replied: bool, pub replied_last: u16, pub links: bool, pub links_days: u16, pub read: bool, pub read_days: u16, pub cap: u16, pub own_names: Vec<String>, pub folders: Vec<ForYouFolder> }`, `Default` = all on, 30, on, 10, on, 61, on, 61, 15, empty, empty. Serde-default every field.
  - `pub struct ForYouFolder { pub folder: Id, pub always: bool, pub max_age_minutes: Option<u32> }`
  - `pub struct SenderStats { by_sender: HashMap<String, Stat> }` with `pub fn of(mb: &Mailbox, now: Timestamp, p: &ForYouPrefs) -> SenderStats` (one pass over all messages in receiving folders of every account; key = `from.address` lower-cased).
  - `pub fn tier(m: &Message, stats: &SenderStats, p: &ForYouPrefs, own: &Own, warned: impl Fn(&Message) -> bool, now: Timestamp) -> Option<Tier>` returning the highest tier of an unread message, `None` otherwise. Never `Tier::Folder` (that is Task 3's).
  - `pub struct Own { pub addresses: Vec<String>, pub names: Vec<String> }` with `pub fn of(s: &Session) -> Own`: addresses from `list::me`, names = `p.own_names` or, when empty, the local parts of his addresses split on `.`, `_`, `-` (lower-cased, 4+ letters).
  - `pub fn is_bulk(m: &Message) -> bool`: has `List-Unsubscribe`, or `Auto-Submitted` other than `no`, or `Precedence: bulk|list|junk`, or the address local part starts with `noreply`/`no-reply`/`donotreply`, or the display name ends with `[bot]`.
  - `pub fn self_triggered(m: &Message, own: &Own) -> bool`: from one of his addresses, or the display name equals (case-insensitive) one of `own.names`.

Rules (`tier`): not read; not `self_triggered`; not `warned(m)`; then the first that holds:
- `NewSender`: `new_sender` on, not `is_bulk(m)`, the sender's first-ever message (whole local mailbox, all folders) is `m` itself or arrived within `new_sender_days`.
- `Replied`: among the sender's last `replied_last` received messages, at least one is `answered`.
- `Links`: the sender's messages received within `links_days`: `link_opened` count * 2 > total.
- `Read`: the same window: read count * 2 > total.

### Task 3: The section in the list

**Files:**
- Modify: `crates/engine/src/list.rs` (`Row`: `#[serde(skip_serializing_if = "Option::is_none")] pub for_you: Option<crate::for_you::Tier>`; in `listing`, after rows are built and before headings: call `crate::for_you::section`).
- Modify: `crates/engine/src/for_you.rs` (add `section`).
- Modify: `crates/engine/src/session.rs` `View` (`#[serde(default)] pub for_you_all: bool`, the "Show all" toggle; reset when the folder changes).
- Test: `crates/engine/src/for_you_tests.rs`

**Interfaces:**
- Consumes: Task 1 `tier`, `SenderStats::of`, `Own::of`, `ForYouPrefs`.
- Produces: `pub fn section(s: &Session, out: &mut Vec<Row>)` and `pub fn applies(s: &Session) -> Option<Where>` with `pub enum Where { AllMail, Inbox }`.

Rules:
- `applies`: no search, sort is Date, not Categories; `AllMail` when `view.scope == Scope::Inboxes && view.all_mail && view.kind.is_none()` and `prefs.for_you.all_mail`; `Inbox` when (`Scope::Inboxes && !all_mail && kind.is_none()`) or the selected folder's kind is Inbox, and `prefs.for_you.inbox`.
- AllMail: candidates are the rows already in `out`; a row qualifies by the best `tier` among its unread members.
- Inbox: candidates also include unread messages of the receiving folders (`crate::cmd::filing::receiving_folder`) of the accounts in view that are not Inbox folders. A message qualifies as `Tier::Folder` when its folder has `always: true` and (no `max_age_minutes` or `received` within it), otherwise by `tier`.
- Manually pinned messages are skipped (they stay in "Pinned"). A message whose `max_age_minutes` passed leaves For you even if it is unread.
- Order: tier, then newest first. `Tier::Folder` rows are never capped; the other rows are capped at `cap` unless `view.for_you_all`.
- The section's rows are moved (removed from their place in `out`), inserted at index 0 with `for_you = Some(tier)`; the first gets `group = Some("For you")`; the heading loop in `listing` must start date headings fresh after the section.
- Stats are computed once per list build; the builder may cache `SenderStats` on the session next to the rows cache, invalidated with it.
